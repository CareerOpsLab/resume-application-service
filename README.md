# 岗位定向简历与求职申请服务

这是一个可复用的求职服务 Skill，适用于从顾客资料开始，完成目标岗位分析、匹配评分、定向改简历、岗位筛选和确认范围内的半自动投递。

项目重点是把真实经历和目标岗位要求对应起来，再用可核对的证据完成简历和投递记录。公开仓库只使用虚构或脱敏资料，不公开任何个人信息。

## 能做什么

- 从零整理顾客的真实经历
- 拆解目标岗位 JD 和筛选关键词
- 按岗位重点重组简历内容
- 按统一评分表评估岗位匹配度
- 采用完整内容型 Word 简历版式
- 提供关键改写的前后对照和事实依据
- 生成顾客填写表和岗位投递总表
- 在顾客确认后协助完成半自动投递

## 输出标准

每个推荐岗位都应包含：

- 综合匹配度和分项分数
- 已有匹配证据
- 主要风险和待确认信息
- 定向简历改写方向

每份简历交付前都检查事实一致性、岗位匹配、文案质量、文件版式、顾客授权和隐私安全。

## 怎么使用

调用 Skill：

```text
$resume-application-service
```

然后上传：

1. 顾客填写好的 `templates/customer-intake.docx`
2. 原简历（如果有）
3. 目标岗位 JD、招聘链接或截图
4. 顾客的补充经历、作品集和限制条件

推荐提示词：

```text
$resume-application-service

请先分析，不要直接改写。
请输出：岗位要求、经历匹配点、简历问题、待补充信息和改写方向。
```

## 标准流程

资料采集 → 目标确认 → JD 分析 → 匹配评分 → 简历改写 → 顾客核对 → 简历定稿 → 岗位筛选 → 顾客确认投递范围 → 半自动或人工代投 → 更新投递总表。

顾客确认最终简历和岗位清单后，才可以开始投递。代投递完成后，把所有信息写入 `templates/application-tracker.xlsx`，发送表格链接给顾客自行查看。

## 隐私和安全

仓库中的简历模板和示例已经脱敏。不要上传真实顾客的姓名、电话、邮箱、证件照、身份证件、账号、密码、验证码、真实投递记录或文件元数据。顾客填写的真实资料只在授权的工作环境中使用，不提交到公开仓库。自动投递只能使用顾客已登录的环境，并在每个岗位提交前保留确认节点。

公开示例中的姓名、学校、公司、联系方式和数据必须使用虚构内容或充分脱敏后的内容。发布前应检查文本、DOCX、表格、图片元数据和 Git 提交信息。

## 服务边界

本 Skill 不承诺 HR 沟通、投递状态追踪、面试安排、测评填写或 Offer 跟进。它只负责确认范围内的简历优化、岗位筛选、代投递和投递信息归档。
